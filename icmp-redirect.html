Mekanisme Serangan ICMP Redirect

Pahami bagaimana pesan kontrol jaringan yang punya fungsi sah dapat disalahgunakan untuk mengubah rute host—dan bagaimana mengurangi risikonya.

ⓘ Materi edukasi defensif. Animasi di bawah adalah simulasi konseptual di jaringan dokumentasi, bukan demonstrasi pengiriman paket atau instruksi untuk menyerang jaringan nyata.

Bagian B · Konsep dasar

ICMP memberi kabar tentang kondisi jaringan

Internet Control Message Protocol (ICMP) adalah protokol kontrol yang dibawa di dalam IP. Perangkat jaringan dan host memakainya untuk melaporkan kondisi atau kendala pengiriman—misalnya tujuan tidak terjangkau, TTL habis, atau rute yang lebih baik tersedia.

ICMPv4 Type 5

Redirect: saran rute alternatif

Router yang menerima paket dari host dapat mengirim Redirect ketika mengetahui bahwa host dan next-hop yang lebih tepat berada pada jaringan lokal yang sama. Host diberi tahu bahwa ada gateway yang lebih baik untuk tujuan tertentu.

  • Code 0Network — redirect untuk jaringan.
  • Code 1Host — redirect untuk host tertentu.
  • Code 2TOS + Network — redirect berdasarkan Type of Service dan jaringan.
  • Code 3TOS + Host — redirect berdasarkan Type of Service dan host.
Fungsi yang sah

Bukan selalu serangan

↗

Tujuan protokol: memberi tahu host bahwa gateway lain pada subnet yang sama dapat menjadi next-hop yang lebih baik, sehingga jalur paket lebih efisien. RFC menjelaskan router tetap meneruskan datagram asli.

Dalam desain jaringan modern, rute biasanya dikelola terpusat dan host umumnya tidak perlu belajar rute dari pesan Redirect. Karena itu, penerimaan Redirect sering dinonaktifkan pada endpoint.

Mengapa bisa terjadi?

Kepercayaan tanpa autentikasi kuat

ICMP dirancang sebagai protokol kontrol yang ringan. Format Redirect klasik tidak menandatangani pesan dan tidak membuktikan identitas gateway secara kriptografis.

Risiko protokol dan konfigurasi

Validasi bukan autentikasi

Checksum hanya mendeteksi kerusakan data, bukan pemalsuan sumber. RFC host/router menetapkan pemeriksaan konteks (misalnya relasi gateway, jaringan, dan tujuan); kualitas penerapan dan kebijakan OS menentukan apakah pesan diterima. Jika host menerima pesan palsu atau terlalu mempercayai asalnya, cache rute dapat berubah.

Faktor yang memperbesar risiko

Paparan Layer 2 dan kebijakan host

  • Attacker dapat mengirim trafik pada segmen lokal korban.
  • Host mengaktifkan penerimaan ICMP Redirect atau kebijakan validasinya lemah.
  • Segmen jaringan tidak membatasi perangkat dan pesan kontrol yang dapat masuk.
  • Rute dinamis pada endpoint tidak dipantau atau tidak sesuai kebutuhan.

Countermeasure

Kurangi penerimaan dan deteksi perubahan rute

Terapkan kebijakan berdasarkan peran host/router dan uji dampaknya di lingkungan terkelola sebelum peluncuran luas.

Linux · nonaktifkan ICMP Redirect di host

Sysctl kernel Linux memakai net.ipv4.conf.*.accept_redirects. Untuk host biasa, tetapkan nilai 0 secara eksplisit; cakupan all, default, dan interface yang sudah ada perlu diperhatikan.

Contoh persisten: /etc/sysctl.d/90-disable-icmp-redirects.confIPv4
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv4.conf.eth0.accept_redirects = 0

Ganti eth0 dengan nama interface yang benar. Terapkan dengan sudo sysctl --system, lalu verifikasi nilai untuk all, default, dan interface aktif. Perubahan spesifik versi/distribusi sebaiknya diuji.

Dokumentasi kernel menyatakan nilai fungsional bergantung pada forwarding dan kombinasi conf/all serta per-interface. Default yang dijelaskan: TRUE (host), FALSE (router); jangan bergantung pada default untuk endpoint yang harus menolak Redirect.

Windows · matikan ICMP Redirect IPv4

Jalankan terminal administratif. Sintaks icmpredirects=enabled|disabled tersedia pada konteks netsh interface ipv4 set global.

Command Prompt / PowerShell (Run as administrator)IPv4
netsh interface ipv4 set global icmpredirects=disabled
netsh interface ipv4 show global

Baris kedua membantu memeriksa konfigurasi aktif. Perubahan harus diuji pada versi Windows dan kebijakan organisasi yang digunakan.

Referensi Microsoft yang ditemukan mendokumentasikan opsi nilai untuk perintah ini, tetapi tidak menetapkan satu nilai default lintas versi/konfigurasi. Karena itu, periksa keadaan aktual dengan show global; default Windows tidak diasumsikan di halaman ini.

Filter secara terukur

Batasi ICMP Type 5 pada host atau batas jaringan sesuai kebijakan. Bila fungsi Redirect memang diperlukan, izinkan hanya dari jalur/gateway yang diharapkan; hindari pemblokiran membabi buta yang menutupi kebutuhan operasional.

Segmentasi jaringan

Pisahkan pengguna, server, dan perangkat yang tidak tepercaya; minimalkan perangkat yang dapat mengirim pesan kontrol ke endpoint. Terapkan kontrol akses pada switch/router.

IDS dan monitoring

Pantau ICMP Type 5 yang tidak diharapkan, perubahan route/cache, sumber Redirect yang bukan gateway terotorisasi, dan anomali arus trafik. Kaitkan alert dengan baseline jaringan.

Bagian E · Batasan dan kehati-hatian

Apa yang simulasi ini tidak klaim

Hasilnya bergantung pada implementasi

Animasi menyederhanakan kondisi ketika Redirect diterima. Host dapat memvalidasi sumber dan rute, menolak pesan, atau tidak menyimpan rute sesuai kebijakan dan implementasi. Perubahan konfigurasi juga dapat memengaruhi desain routing tertentu.

MITM bukan berarti dekripsi otomatis

Pengalihan memberi peluang berada pada jalur trafik, bukan otomatis membuka konten terenkripsi. TLS dengan validasi sertifikat yang benar melindungi konten aplikasi; tetap tinjau metadata, ketersediaan layanan, dan risiko konfigurasi/proxy yang lemah.
